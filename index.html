橋梁点検UAVのCPP研究 C++ / ROS2 / Gazebo アルゴリズム設計〜シミュレーション検証

1. 社会的背景

国内の橋梁は建設後50年を超えるものが急増しており、2033年には全体の約63%に達すると推計されている。 道路法は5年に1度、目視での近接点検を義務付けているが、点検員は不足し、高所・水上での近接目視作業には 危険が伴う。自律ドローンによる自動点検が、この負担を軽減する解決策として期待されている。ドローンで 構造物全面を漏れなく点検するには、撮影経路を自動生成する技術——Coverage Path Planning（CPP、 被覆経路計画）——が要る。

2. トラス構造特有の課題

少なくとも岐阜県の運用基準では、トラス橋・アーチ橋・斜張橋・吊橋のような「構造が複雑な橋梁」は、 UAV点検支援技術の適用対象から明示的に除外されている。除外理由は「構造が複雑」としか 記されておらず、遮蔽が原因なのか、衝突リスクなのか、撮影品質の問題なのかは明文化されていない。 トラス橋は多数の細長い部材が様々な角度で交差する構造を持ち、部材同士が密に接近するため安全に 飛行できる空間は狭く、部材の背後や接合部の内側は特定の方向からしか撮影できない。本研究は、 この「複雑さ」を追認せず、除外されている理由そのものに技術的に取り組む位置づけを取る。

3. 先行研究とその取り入れ方

UAV点検が「近接目視の代替」として制度上認められるための基準を辿ると、一貫して問われているのは 移動の効率ではなく撮影画像の品質である。品質保証には、①分解能保証（撮影距離・角度から 実際の解像度を計算し、要求解像度を満たすことを保証する）、②モーションブラー回避（静止して 撮影し、動きながら撮ると生じるブレを避ける）の2要素がある。

羽田ら（2025）は、ジンバルを活用しながら分解能保証を満たしつつ停止回数を最小化する視点生成 アルゴリズムを提案し、従来手法比で検査時間を47.7%削減している。本研究はこの品質保証という枠組み （分解能保証の数式・撮影距離の考え方）を土台として採用した。ただし同手法は対象面を先に領域分割 してからカメラ位置を決めるため、他部材による遮蔽を分割の時点で考慮していない。密にトラス部材が 交差する本橋梁に適用して定量比較したところ、分割時点で「見えている」と判定された被覆率91.9%に 対し、実際に遮蔽・画角まで考慮した被覆率は41.4%までしか届かなかった。著者ら自身も論文中で 「非平面・密な部材交差構造への適用効率は改善が大きくない」と限界を認めており、本研究はこの ギャップを定量的に裏付けた形になる。

4. 現状：工夫と結果

そこで本研究では、対象面を先に分割せず、3D空間に候補位置を密に置き、それぞれの候補が実際に どの面を（遮蔽・画角・分解能保証込みで）撮影できるかを個別に評価してから視点を選ぶ方式を採用した。 空間側を探索することで、複数部材が交差する接合部でも、たまたま両方が同時に見える候補位置を 自然に拾える。以下はstandalone幾何計算での結果（Gazebo実機シミュレーションでの再現検証は進行中）。

  • 98.2% 被覆率（候補を尽くすまで探索） 候補位置225、対象点19,648（部材53本のトラス橋）に対する結果。90%到達時点では85位置で済み、追加140位置のほとんどは残り10%を拾い切ることに使われている。
  • 353点 残る未被覆点の内訳 CROSS_BEAM 132点・HORIZ_BRACE 221点のみ——複数部材に囲まれ特定の1方向からしか見えない、接合部近傍の面に絞り込まれる。安全離隔を保ったまま到達できる位置が存在しない、構造上の限界。
  • 41.4% 先行研究(羽田Algorithm1)を適用した場合の実測被覆率 分割時点でのclaimed値は91.9%。密な部材交差構造では遮蔽を見落とし、実測との間に50.5ポイントのギャップが生じることを定量的に確認した。
  • G(d,θ)≤s_req 分解能保証式（実装済み） 既往研究のT型橋脚実験値（f=97.9mm）を用い、距離・入射角から実効GSD（1pixelが対象物上で対応する実寸）を計算する式をROS2ノードに実装・動作確認。

AIツールとの向き合い方

研究の方針決定でAIエージェントを使うときの判断軸

サブエージェントを使うとき、効く使い方と効かない使い方がはっきり分かれると気づいた。判断基準は一つ—— 外部から情報が入るか、自分では見えない死角を突くか。同じモデルに討論させるだけでは、もっともらしく 見えても判断材料は増えない。効くと分かった使い方は4つ。

① 反証タスク

擁護させず、成功/失敗が判定できる課題を渡す。「反証できなかった」という報告自体が情報になる。

② 前提の掘り起こし

議論させず列挙させる。自分では見えない隠れた前提の網羅は、判断ではなく網羅なのでエージェント向き。

③ 隣接分野からの輸入

経路計画の外（非破壊検査・計測工学・写真測量規格など）を探させ、新しい定式化を持ち込む。

④ 制度・実務からの検証

難しさがアルゴリズムではなく、制度・運用側の要求から来ている可能性を潰す。

実例 · 2026-08-20 「品質保証は視点数を増やせば力ずくで達成できる」という行き詰まりに直面したとき、エージェントに議論させる前に 自分の実装を測った。視点85→227で被覆率は90.1%→98.2%に上がるのに、1枚あたりの達成分解能は0.456→0.458と ほぼ不変——増分は全て被覆率に使われ、品質保証には効いていなかった。さらに掘ると、被覆判定が機体の実座標ではなく 計画上の視点座標で行われており、到達判定は0.4mのずれを許容していることが判明した。
