プロジェクト実績

橋梁トラスUAV点検 経路計画（Coverage Path Planning）研究 · 2026年〜継続中

個人研究・単独実装 C++ / ROS2 / Gazebo アルゴリズム設計〜シミュレーション検証

課題

国内の橋梁は建設後50年を超えるものが急増しており、2033年には全体の約63%に達すると推計されている。 道路法は5年に1度、目視での近接点検を義務付けているが、点検員は不足し、高所・水上での近接目視作業には 危険が伴う。ドローンによる自動点検の解決策として、構造物の表面を漏れなく撮影する飛行経路を自動で 組み立てる技術——Coverage Path Planning（CPP、被覆経路計画）——が要る。対象の明石大橋のような トラス橋は、細い部材が何本も様々な角度で交差する構造を持ち、CPPの中でも特に難しい部類に入る。 部材同士が密に接近するため安全に飛べる空間は狭く、部材の裏側や接合部の内側は特定の方向からしか 撮影できない。

自分の役割

アルゴリズムの設計からC++実装、ROS2 + Gazeboでのシミュレーション構築、結果の検証・分析まで一人で担当。 指導教員の方針を実行するだけでなく、研究全体の前提そのものを自分で検証し、方針転換を主導した。

前提を自分で測って検証し、設計を作り直した

3D構造物点検のCPP研究の主流は、①構造物の表面を撮影できる位置（ビューポイント）をいくつか生成し、 ②その全点を回る最短順序を求める（巡回セールスマン問題・TSP。点の数が増えると計算時間が急激に 増えることで知られる）、という2段階の設計を取る。本研究も当初、「ビューポイントが多いとTSPが計算爆発 するから、訪問順序の工夫で経路を短くする」という前提から出発していた。

だが実際に必要なビューポイント数を測定すると I=68〜190（専門家の想定は数十、自分の直感は数百だったが、 実際は百程度）で、既存のTSPソルバのベンチマークではこの規模は1秒未満で解ける可能性が高いと分かった。 研究全体を駆動していた前提そのものが揺らいでいることに、自分で気づいた。

振り出しに戻り点検制度（国の点検要領・自治体の運用基準）まで遡ると、UAV点検の成否を分けているのは 移動の効率ではなく撮影画像の品質だと分かった。分解能保証（写真が診断に使える解像度で撮れているかを 撮影距離・角度から計算して保証すること）と、静止して撮ることによるモーションブラー（動きながら 撮ると生じるブレ）の回避を研究の軸に据え直し、連続移動しながら撮影する既存アーキテクチャから、 止まって撮る視点生成方式へ、経路計画そのものを設計し直した。

成果

  • 97.68% 被覆率（和集合モデル） 橋梁を53本の独立した箱ではなく1つの立体として扱い直し、重なり内部の実在しない点を除去。指標の測定条件依存（旧: 3.0ポイント幅の揺れ）を解消した。
  • 2.32% 未被覆点の要因分解 78.7%は部材間隔0〜1.0mで機体が物理的に入れない構造上の限界。残りは候補点の解像度不足で、格子を細分化すると98.21%まで改善することを実証済み。
  • I = 68–190 実測ビューポイント数 専門家の予想（数十）でも自分の直感（数百）でもなく、実測により「百程度」と決着させた。
  • G(d,θ)≤s_req 分解能保証式（実装済み） 既往研究のT型橋脚実験値（f=97.9mm）を用い、距離・入射角から実効GSD（1pixelが対象物上で対応する実寸）を計算する式をROS2ノードに実装・動作確認。

AIツールとの向き合い方

研究の方針決定でAIエージェントを使うときの判断軸

サブエージェントを使うとき、効く使い方と効かない使い方がはっきり分かれると気づいた。判断基準は一つ—— 外部から情報が入るか、自分では見えない死角を突くか。同じモデルに討論させるだけでは、もっともらしく 見えても判断材料は増えない。効くと分かった使い方は4つ。

① 反証タスク

擁護させず、成功/失敗が判定できる課題を渡す。「反証できなかった」という報告自体が情報になる。

② 前提の掘り起こし

議論させず列挙させる。自分では見えない隠れた前提の網羅は、判断ではなく網羅なのでエージェント向き。

③ 隣接分野からの輸入

経路計画の外（非破壊検査・計測工学・写真測量規格など）を探させ、新しい定式化を持ち込む。

④ 制度・実務からの検証

難しさがアルゴリズムではなく、制度・運用側の要求から来ている可能性を潰す。

実例 · 2026-08-20 「品質保証は視点数を増やせば力ずくで達成できる」という行き詰まりに直面したとき、エージェントに議論させる前に 自分の実装を測った。視点85→227で被覆率は90.1%→98.2%に上がるのに、1枚あたりの達成分解能は0.456→0.458と ほぼ不変——増分は全て被覆率に使われ、品質保証には効いていなかった。さらに掘ると、被覆判定が機体の実座標ではなく 計画上の視点座標で行われており、到達判定は0.4mのずれを許容していることが判明した。
